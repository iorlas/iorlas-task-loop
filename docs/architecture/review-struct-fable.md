## Top 10 by importance

1. **STRUCT-FABLE-02** The `stores` layer holds on paper only: 76 modules of app, cli and dash import the effectful `contracts.{stores,locator,runlife,fence,guard,locks}` directly, 29 sites build `JsonStore(...)` by hand, and the layers contract allows every one of them.
2. **STRUCT-FABLE-01** `Engine` is a service locator with 86 imported modules, 35 `cached_property` parts built over itself, and 42 modules typed `host: Any`; it is also the third most-churned file in the tree.
3. **STRUCT-FABLE-05** `contracts` is the biggest and the most volatile layer (5606 SLOC; 4 of the 7 most-churned files), and it is where the file stores, the bd fence, the flock and the run reconciler live.
4. **STRUCT-FABLE-03** Lazy imports (`sys.set_lazy_imports("all")`) plus a cycle check that is applied only to the retired skill folder table mean an intra-slice import cycle can never fail anywhere; two already exist behind `TYPE_CHECKING`.
5. **STRUCT-FABLE-04** `contracts/ports.py` is one 511-line module with 23 protocols; `Git` alone has 54 methods and the file has 132 importers: every module that reads one ref depends on the whole mutation surface.
6. **STRUCT-FABLE-13** The install's own path is an ambient module global (`adapters/ident.py:45 PLUGIN_ROOT`) read by 27 modules; this is the structural reason the "job bundle" (Z05, R2) cannot be frozen without a rewrite.
7. **STRUCT-FABLE-07** Four spellings of "the edge" (`tl.py`, `app/wire/real.py`, `app/launch/*`, `cli/*`), two composition roots (`Engine`, `LoopEnv` of ~45 lambdas) and `tl.py` outside the linter.
8. **STRUCT-FABLE-09** The dashboard's import isolation is a sibling-root rule, not a layer: dash is not in the `layers` contract, reads 8 config-dir file families through `contracts.stores`/`locator` directly, copies `loop_key`, and loads engine code by string at runtime.
9. **STRUCT-FABLE-16** Delegate's `app/env.py` is a module-level service locator (`config_dir()`, `states()`, `history_store()`, `update_state()`), the exact disease task-loop spent SPAWNCAP/edge rules curing.
10. **STRUCT-FABLE-24** The real database schema of the factory is `ConfigDir`: 74 path methods, no table of "who writes this family", so the "one writer per fact" invariant the RCA asks for has no place to be checked.

## What I think you are NOT thinking about

1. **The gate measures the wrong invariant, so every refactor slice is a transfer, not a reduction.** 1183 commits in a month, and the most-churned files are the ones the rules call stable (`contracts/config.py`, `ports.py`, `paths.py`). Nothing in `just check` says "this change added an importer of an effectful module" or "this change added a reader of a file family". Both are one AST pass each (STRUCT-FABLE-02, -24). Until they exist, Codex will keep satisfying the SLOC cap by splitting a file into two that share a host, and the review documents will keep finding the same locator.
2. **Lazy imports changed what "import" means and nobody updated the rules.** With `set_lazy_imports("all")`, the `PLC0415` ban on function-level imports (meant to keep the graph static and visible) is enforcing a property the runtime no longer has: every module-level import is now a function-level import in effect. Cycles are free, import-time side effects are use-order, and `tests/rules` has no test that runs the suite eagerly. The release does (`dev/release.py:39-40`); the suite does not.
3. **The two apps are converging on the same architecture by hand, one rule at a time, and the delegate copy is 3 to 6 months behind.** Delegate has today what task-loop had before SPAWNCAP/edge rules/import-linter: module-level stores (`app/env.py`), stderr in the record layer, a flat app, an AST layer test. Every rule task-loop added will be re-derived there. The shelf is the place for the rules (an import-linter preset and the `gate_rules` module as a package), not just for the primitives; shelf's `AGENTS.md` already says the toolchain is "the reference every consumer inherits".
4. **`ConfigDir` is a schema without a migration story, and R1 (SQLite) will inherit every one of its 74 families as a column unless the family table exists first.** Writing `WRITERS` (STRUCT-FABLE-24) is also the inventory R1 needs; doing R1 without it means guessing which of 40 families are authority and which are evidence.
5. **The "edge" is a convention with four spellings and a rule test that lists them by path.** `test_env_below_edge.py` enumerates `SPAWNER_EDGES` and `IDENTITY_SITES` by string. Every new verb that builds a port needs a line there. The structural fix (one `edge` package the linter can name) removes the lists; until then, the test is a ratchet on a thing that has no name in the code.
6. **The install path is the one ambient global the env ratchet forgot, and it is the one that makes the hop problem (Z05, A.F04, A.F06) structural.** A bundle you cannot name in a value cannot be frozen in a manifest. STRUCT-FABLE-13 is a precondition for R2, and it is small.
7. **The dashboard's read side is a second engine.** `dash/readers/*` re-implements liveness (`shown`), parks, loop state, run bundles, beads cache, with its own `loop_key`. When R1 moves authority into one store, the dashboard must be a client of that store or it becomes a second reader of the DB with its own idea of liveness. Decide client-or-layer (STRUCT-FABLE-09 / -34) before R1, not after.
8. **Protocols are being used as a type-checker-shaped service locator.** `CheckHost` (14 members), `CloserHost` (sum of 9), `host: Any` in 42 files: pyrefly passes, and the authority split the docstrings describe does not exist. A member cap on `*Host` protocols costs one rule and makes the next locator visible in diff review.

## Where I disagree with the existing documents

- **Z17 severity (P3) and order (wave 3, after Z04).** Effects in contracts is the reason Z04's CAS has no home and the reason 76 modules bypass `stores`. The cheap enforcement half (STRUCT-FABLE-02, one forbidden contract with a shrinking ignore list) belongs in wave 1; the move itself can wait.
- **Z16 / R5 as "L, wave 3".** The two S-sized rules (STRUCT-FABLE-11 slice-count cap, STRUCT-FABLE-21 host-member cap) can land now and stop the locator from growing while R5 waits for R1; the zoom-out ranks only the rewrite.
- **c4-task-loop's layer table says `layers` "holds".** It holds because `layers` permits skipping: app -> contracts directly is legal, which is the whole problem. "No upward static import found" is true and not the question; the question is whether the middle layers carry anything, and `stores` does not.
- **c4-task-loop item 13 ("tl.py sits outside the layer rules") is listed as a smell, not a defect.** It is the real CLI, 460 lines, and it violates `layers-no-skips` (`tl.py:75` imports adapters). A rule that excludes the main entry point is a rule about the files that do not matter.
- **encapsulation-layers L04 wants domain purity enforced by a transitive effect prohibition.** Agreed on the goal; the mechanism proposed there (a planted-import test) checks the rule, not the tree. The AST pass over `contracts/` for effect calls (STRUCT-FABLE-05) and the forbidden contract (STRUCT-FABLE-06) are the two things that fail on today's code.
- **extraction-delegate-dash's direction (pull the dashboard further out).** Every structural leak on the dash's read side comes from it being outside the layers while reading engine files. Either it becomes a true client (one feed verb, STRUCT-FABLE-09) or it comes inside. "Further out, reading the same files" is the worst of both.
- **The RCA's "why the factory did not catch it": "no test asserts exactly one reader of X".** Half right. The reason there is no such test is that there is no object to assert it on: writers and readers are spread over 74 path-builder methods with no table. STRUCT-FABLE-24 is the missing object; ZOOMOUT-INVARIANTS cannot be written without it.
- **c4-delegate "Dependency direction and its enforcement" reports the layer test as adequate.** It checks package names and a `NO_WORLD` set for domain; it does not see that `app/env.py` is a locator, that `contracts/stores.py` prints, or that `app` has no internal structure. The test passes on a design task-loop already decided was wrong for itself.
- **zoom-out section 1, line 10: "The import rules hold and prove little".** Agreed, with a sharper statement: the rules prove the thing they measure (names), and the gate measures nothing else. The fix is not fewer rules; it is three rules that measure effects, families and fan-out (STRUCT-FABLE-02, -11, -24), each one AST pass.
