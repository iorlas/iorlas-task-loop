## Top 10 by importance

1. **SPLIT-OPUS-01**: the worker-run wire is written twice (task-loop 498 lines, delegate 350 lines, different class names). Keep one copy, owned by delegate, and have task-loop import it.
2. **SPLIT-OPUS-02**: the `Stores` bundle is half-adopted. Manifests, parks, landed receipts and loop files (exactly Z04's racing files) are built by hand outside it, so a CAS added to the bundle covers none of them. Finish the bundle first.
3. **SPLIT-OPUS-03**: eight places read `.task-loop.json` by hand. Make one `ProfileSource(repo, at=base|tree|commit)`. Z01/Z02 come from this bug class.
4. **SPLIT-OPUS-04**: delegate's status is modelled three times, and task-loop's copy drops delegate's `asks` and `holds`. The owner's questions from delegate never reach the dashboard.
5. **SPLIT-OPUS-05**: `events.jsonl` has two writer paths with different retention (a held `applog` handle plus 7-day prune, and a rotating `EventLog` that nothing calls). There are five JSONL append implementations in total. Make it one log substrate.
6. **SPLIT-OPUS-06**: new shelf package `plugin-release`. The marketplace has 6 plugins, only task-loop has a release pipeline (1,143 lines), and delegate bumps its version by hand.
7. **SPLIT-OPUS-07**: `app/release` is three slices in one folder: the release pipeline, install selection, and the mid-run hop. It also holds the delegate route seam and branch tidy.
8. **SPLIT-OPUS-08**: engine domain imports the dashboard's view contract (`OwnerCause`, `Stick` from `contracts/dash.py`) in 8 modules. The dependency is inverted.
9. **SPLIT-OPUS-09**: process identity. Delegate uses pid+start everywhere. task-loop has both APIs and calls the pid-only one 14 times against 4 for the identity one. Join on delegate's rule.
10. **SPLIT-OPUS-10**: test fakes are duplicated: two bd fakes (only one held to the contract), three delegate fakes, five git fakes, two dashboard fixture builders.

## What I think you are NOT thinking about

1. **Half-finished migrations are a bigger volume source than missing abstractions.** The `Stores` bundle vs 15 direct `JsonStore(`; `EventLog` vs `applog`; `pid_alive` vs `proc_alive`; `dash/jsonl` vs `JsonlStore`; three bd/delegate fakes where one is contract-held. Each half migration doubles the code and halves the guarantee. Extraction moves lines. Finishing these deletes them, with zero release choreography. None of the five extraction lenses counts them, because they are not shelf-shaped.
2. **Shelf packaging cost grows with the number of packages times consumers.** Each package is a tag, a `vendor.json` row with commit and tree hash, a drift test, a sys.path bootstrap, in two apps. Z23 shows they already drift at 7 packages. Extraction-synthesis proposes roughly 20-30 more. Without D0 solved first, every extracted package is a new drift surface. D0 is a prerequisite, not item 1 of a list run in parallel.
3. **The Python split (3.12 delegate, 3.15 task-loop) silently caps every join.** A shared shelf package must support the lower version. The codec join (OPUS-27) and the wire join (OPUS-01) need delegate on 3.15/uv. That one change unblocks more joins than any extraction.
4. **The owner has two inboxes and doesn't know it.** Delegate raises `asks` (with an answer field) in `status --json`. task-loop's snapshot drops them (`contracts/snapshots.py:47-55`). On the Mac at night, a delegate question waits forever while the dashboard shows "nothing needs you".
5. **Agents navigate by name, and the factory has many same names:** `RunLog` x2, `push_judge.py` x2, `fixer.py` x2, `gate.py` x2, `Result` x2, `lane` x3, `NeedInput` x2 across apps, `RunRequest` x2 across apps. With Codex writing all code from briefs, each collision is a standing chance of a wrong-file edit. That's a measurable defect source nobody tracks.
6. **The worker-run boundary costs about as much as a fifth of delegate.** ~600 task-loop lines (wire + parser + route + adapter) and a 1,759-line generated `contract.json` serve one consumer that is always installed alongside. The "two apps" story is maintained for a standalone use (sessions calling `route.py`) that the one-plugin form keeps anyway.
7. **Test volume is where duplication is cheapest to delete and nobody is looking.** 5,060 lines of `tests/support` with five git fakes and three delegate fakes. The extraction lenses push procsim and gitsim to shelf (moving lines). Collapsing the fakes inside the app removes lines and drift risk without a tag.
8. **"Contracts" is 16% of the engine and the least protected layer.** It holds stores, the fence (bd effects), the dashboard wire, the delegate wire and the domain types the dashboard owns. Most of the R-A "fact without owner" bugs pass through it, and import-linter treats all of it as one bottom layer.
