Thesis. The C4 documents draw one trust line, "router to worker: the sandbox line". That line does not hold. Every place where
**writer-authored bytes are executed by a host process holding Denis's credentials** goes around it. Those places are host checks,
the gate inside the pre-push hook, planner-authored ad-hoc checks, repo pre-commit hooks, mise, the link checker, and every
`claude -p` worker. The diagrams leave out all of these edges. Without `--exec-allow`, the factory already lets a prompt-injected
writer reach the SSH agent one check round later. Z11 argues about the front door while the back door is open.

---

## Top 10 by importance

1. **SEC-OPUS-02**: host checks run writer-edited code with `SSH_AUTH_SOCK`, `GIT_SSH_COMMAND` and the real `HOME`. Writer code gets push credentials **today**.
2. **SEC-OPUS-01**: the planner, a model that reads bead text, writes ad-hoc check argv. The engine runs that argv on the host. The only guard is a lint that checks the command can run.
3. **SEC-OPUS-09**: `claude -p` is a write lane with no OS sandbox. On the devbox it is the only fallback after Codex. It can read every credential, forge `results/` receipts, POST to the dashboard and write bd as anyone.
4. **SEC-OPUS-40**: run the factory as a separate Unix user (or container) without Denis's key. This one lever closes most of the list.
5. **SEC-OPUS-23**: trust-root files (`.task-loop.json`, `justfile`, `.pre-commit-config.yaml`, `mise.toml`, `.claude/settings.json`, `AGENTS.md`) can be edited by the writer and only face an ordinary model review.
6. **SEC-OPUS-19**: follow-up beads written by workers go straight into the ready queue (cap 3 per run). This lets a prompt injection copy itself into new beads.
7. **SEC-OPUS-17**: dashboard writes have no authentication. Any tailnet peer or local process can file "owner" answers, which reach the next brief with owner authority.
8. **SEC-OPUS-07**: a Codex sandbox escalation is approved by a model that reads the writer's own justification. The write-step sandbox is only as strong as one prompt.
9. **SEC-OPUS-14**: the pre-push judge runs on the client and can be bypassed. The real delivery boundary would be GitHub rulesets with deploy keys, and neither exists.
10. **SEC-OPUS-04**: an `--exec-allow` entry `just X` lets the writer run any recipe (`just X evil`, `just --command`), and task-loop silently drops the delegate guard (SEC-OPUS-05).

## What I think you are NOT thinking about

1. **The writer does not need to escape the sandbox; it only needs to wait one round.** Every check round runs writer-edited tests, recipes and
   `.venv` contents on the host with your SSH agent (`tl:adapters/childenv.py:39`, `tl:adapters/checks_argv.py:16`). On lifesim on the
   Mac, that includes the keychain and every logged-in CLI. The Codex network ban only delays the payload by one round.
2. **Your planner is a remote shell.** Bead text, follow-ups written by earlier workers, comments with forged authors, and anything that
   arrives through `refs/dolt/data` all reach a model whose output becomes host argv (`lint.py:118-135`). Nobody reviews a planner's checks before they run.
3. **The factory writes into your own agent's config.** A landed `.claude/settings.json`, `AGENTS.md`, `mise.toml` or `.pre-commit-config.yaml`
   runs in your interactive Claude sessions and in the always-on Remote Control sessions, which are pre-trusted per
   `~/.devbox/claude-rc.txt`. That makes it persistence into your account, not only into the factory.
4. **On Linux, "the fallback writer" means "the unsandboxed writer".** OpenCode lanes refuse on Linux (`dg:app/launch.py:145`), so a Codex quota-out
   routes writes to `sonnet-5.5` through `claude -p` (`dgs:routing.json:161-193`). It has your `HOME`, network, `bd` and the dashboard.
   Quota exhaustion is a security event, and nothing records it as one.
5. **One key reaches everything.** The devbox key that pushes lifesim also pushes homelab, the marketplace (code execution on both
   machines) and shelf. The worst case is not a broken lifesim main. It is your NixOS hosts and every installed plugin.
6. **Refresh-token rotation is a denial of service you will cause yourself.** The exec-allow overlay copies credential handling into a per-call directory
   (`codex_policy.py:29-36`). Your own CLAUDE.md says refresh tokens can be single-use. Expect "Codex logged out" on both lanes the
   first week it ships.
7. **The Mac sandbox is `(allow default)`.** Seatbelt profiles that allow by default leak through Mach services (launchd, LaunchServices,
   AppleEvents) and unix sockets. OpenCode itself, with its formatters and LSPs, runs outside the sandbox on files the writer just edited.
8. **You never tested the base assumption on the devbox.** It is a container. Whether Codex's Landlock and seccomp sandbox actually
   blocks network and writes in that container has never been measured (SEC-OPUS-42).
9. **The tracker is a public-ish data channel.** Worker answers become bd notes and follow-ups, which travel to GitHub under `refs/dolt/data`.
   A worker that read a secret has a path to publish it without any network of its own.

## Where I disagree with the existing documents

- **c4-system trust table, "Router to worker: the sandbox line".** That is the wrong line. The real line is "bytes the writer controls, executed by a credentialed
  host process". It is crossed by checks, the gate in pre-push, planner ad-hoc checks, repo hooks, mise, the link fetch and every `claude -p` call. The
  diagrams draw none of those edges.
- **Z11's alternative, "the engine already runs checks on the host after each write ... add a declared engine command".** That is not safer. It is the same hole with a
  one-round delay, because the host check runs the writer's edited code with SSH. Z11 is right to refuse exec-allow, for the wrong reason. The fix is a
  sandbox for checks (SEC-OPUS-02/03), and then exec-allow becomes moot.
- **rca-zoomout-three option (c), "exec-allow only for tools that run no writer-edited code (`typos`, `fmt-check-changed`, ...)".**
  `fmt-check-changed` is a just recipe, and recipes are writer code. Prefix matching plus `just a b` means any recipe runs (SEC-OPUS-04). Only absolute binaries with fixed args qualify.
- **Z01-Z03 ranked as the top P1s.** They harden a client-side hook that `--no-verify` bypasses (`childenv.py:56-58` says so). They are
  correctness work, not security work. GitHub rulesets (SEC-OPUS-14) should come first, or at least alongside them.
- **Z24, GIT_CONFIG `pushInsteadOf` as "push protection for all lanes".** It holds for Codex, which has no network anyway. It does not bound `claude -p`, which can
  `env -u GIT_CONFIG_COUNT`, `git -c url...`, `gh api`, or run `ssh` with `~/.ssh/id_*` directly. That is another text-level fix to an OS-level problem.
- **Z08, "the dashboard spawns `tl VERB`".** That is good hygiene, and it fixes nothing in the trust model. The problem is the missing authentication (SEC-OPUS-17/38) and
  GETs with no Host check (SEC-OPUS-16), not which process does the write.

  whole Linux posture rests on (SEC-OPUS-42), not as a note.
