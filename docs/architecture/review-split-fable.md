## Top 10 by importance

1. **SPLIT-FABLE-22** One plugin, one release, one vendor set, one Python: stop being two products that are always installed together.
2. **SPLIT-FABLE-01** A `worker-run` shelf package owns the contract once: records, reasons table, argv builder, fake route; delete task-loop's 2,550-line hand-copied client.
3. **SPLIT-FABLE-02** Delegate becomes an in-process library call from the engine; `route.py` stays as an 11-line CLI for the orchestrator.
4. **SPLIT-FABLE-03** task-loop has three store layers (ad hoc `XStore(cfg)`, the `Stores` bundle, standalone `ParkStore`/`LandedStore`/`RunLocator`/`LoopFiles`); make it one, as the prerequisite of Z04's CAS.
5. **SPLIT-FABLE-09** `git_porcelain` is vendored into task-loop (4,511 lines, shipped in every install) and imported by nothing in `src/`; delete the copy now, converge later.
6. **SPLIT-FABLE-11** The dashboard is one process that imports engine code at runtime; make `taskloop_dash` a slice of `taskloop` and delete the `Ports` indirection and the import-rule theatre.
7. **SPLIT-FABLE-07** Three lock wrappers over one `process_lock`; task-loop's re-implements the holder record the vendored package already provides.
8. **SPLIT-FABLE-06** Nine JSONL families, five writer implementations, two hand-rolled age retentions; one `jsonl_log` with age retention, held handles and a cap.
9. **SPLIT-FABLE-16** task-loop re-finds worker transcripts and reads OpenCode's SQLite although the wire answer already carries `transcript` and `context_k`; delete `adapters/opencode.py`.
10. **SPLIT-FABLE-05** (contrarian) Drop msgspec; one stdlib record codec for both apps, so `tl.py`, the hooks and `route.py` run on one plain `python3` and the uv shim, the PEP 723 drift test and the `sys.executable` mismatch go away.
