1. Registration barrier. Acceptance: an authorized continuation runs the saved native session only after its exact worker identity is durably registered for the current recovery generation; refused, unavailable, or stale registration never permits target execution. Concurrent callers permit at most one worker.
2. Fenced session and result callbacks. Acceptance: callbacks from a replaced owner, recovery generation, or worker cannot change the session, execution, or accepted answer; the current callback can capture its result once, and identical retries are idempotent. A different session is an explained conflict, with no fresh-session fallback.
3. Adoption after lost acknowledgements. Acceptance: reopening after registration commits but its acknowledgement is lost observes and retains the registered process without spawning again; unknown liveness blocks execution, captured work is collected, and another continuation requires confirmed absence of the previous owner and entire worker group. Deterministic crash tests assert execution counts across each boundary.

## Implementation
1. Extend the recovery record with validated execution progress and the registered continuation worker, retaining the authorization's exact attempt key, owner identity, generation, token, original entry/worker identities and saved session. Represent closed progress/outcome vocabularies as enums with one storage codec. Keep execution facts in the attempt/execution owner and recovery progress in `RecoveryStore`; do not duplicate authoritative execution state. Extend ownership through typed store methods, following the existing `RecoveryStore` to `AttemptStore` transaction pattern, so revision checks and worker replacement commit atomically. SQL and connections remain inside store modules.
2. Treat the added persisted execution interpretation as an incompatible schema upgrade: bump version 23 to 24 even if the JSON table needs no new columns. Drain old attempts before the owning upgrade operation discards the old database. Do not add migration, fallback, backup/restore, or teach old processes to write the new interpretation. Validate malformed or incomplete execution records as unavailable, preserving them. Schema-version assertion updates are included in the file estimate.
3. Implement `continue_session` as a narrow callable operation composed with the existing authorization, process observation, custody, clock, claim and execution ports. Accept an explicit attempt and current recovery ownership, not display text. Hold slot custody throughout authorization/reconciliation and execution. Reconcile an existing execution record before requesting another authorization; part 1's authorization requires old entry and worker absence and therefore cannot be blindly rerun against a live continuation. Recheck held/superseded/released work, reservation, claim, deadline and drain at the relevant store boundaries. Preserve the stored base, input, harness/model/access policy and original deadline. Do not reset the checkout, repeat setup, create a new attempt, or allocate a new session.
4. Record execution intent in a short transaction before invoking any external execution. Build with `resume=intent.session` through `AgentLaunch`, and use generation-specific launch/output/evidence paths through `EvidenceFiles`. Release every write transaction before filesystem or harness actions. The started callback atomically checks current intent ownership and attempt revision, binds the worker's full identity, and updates the attempt through its owning store. Returning from the callback releases the shelf's permit only after commit. Duplicate registration for the exact same worker succeeds idempotently; a different worker or replaced ownership refuses. Register drain action ownership through the existing action API; unresolved external action results remain uncertain for observation rather than being marked finished.
5. Bind session callbacks, terminal result capture, capture retries and answer completion to the recovery generation/token and registered worker. Add a shared optional typed execution fence to the existing internal store operations, preserving ordinary call sites. An ordinary callback without that fence must fail once recovery owns the attempt; key/reservation equality alone is insufficient. Check the fence and mutate within the same transaction. Matching saved-session reports succeed; a different current session conflicts. A stale callback must not even mark the current session conflicting. Use immutable generation-specific evidence references so a late callback cannot overwrite accepted files before a database fence rejects it. Reuse existing decoding, validation and collection after the current execution is captured; never rerun the agent to complete those phases.
6. On lost acknowledgement, reread durable registration before any new start. Observe the stored boot/start/group identity through the owning process port. A matching process is adopted as existing work, not attached through an invented process handle and not restarted; an unknown identity remains unresolved. If execution is captured, return collection/completion without a launch. Only confirmed absence of the previous owner and worker group permits a later authorized generation. A crash before durable worker registration cannot have permitted target execution; a crash after registration, including before permit acknowledgement, requires observation of that exact worker. Never infer permission from absent logs, output files, a free lock, elapsed age, or an exception. Do not compensate by killing or rolling back registered work.
7. Wire a directly callable recovery operation in composition with bounded registration writes and the existing run adapter. Keep `Attempts.execute`, admitted-entry launch, fresh repeats and merge execution on their present default path. The new operation must be independently consumable by later lifecycle integration without moving policy into composition or requiring an owner command. Preserve informative generic outcome explanations supplied by the relevant adapters.
