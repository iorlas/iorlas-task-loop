1. The wiring tree today

Not one tree: three roots (composition, cli_composition, dash_composition) and two entry processes that wire themselves.

  • __main__ → cli → cli_step
    • cli_composition 28 imports builds the step openers
      • composition 28 imports builds attempts, checking, releaser, launcher…
        • leaves: Store, GitViews, EvidenceFiles, tracker claims, Launcher
    • dash_composition → cli_composition.open_reads
  • attempt_entry.main own wiring → composition.open_attempts
  • check_entry.main own wiring → composition.open_checking; imports attempt_entry

2. Where the tree breaks

Repeated wiring
  • Store(SCHEMA) + close_shared(): 8× in composition, 6× in cli_composition, 1× in launch
  • AttemptStore(...) built several times in composition
  • GitViews(...) in cli ×2, cli_step, both entry mains
  • Both entry mains repeat tracker lookup, a stderr log and a catch-all handler
Non-root code that builds real things
  • launch.py:150 opens the database itself
  • attempt_status and dash_task build CheckStore, HoldStore, SetupStore (7 sites)
  • land_check and validate import the wiring root composition for one type
  • stopping and Checking are threaded through 3+ layers to reach one consumer

4. Shared modules that bundle unrelated things

attempt_types
54 importers
Attempt and admission types (used by 6 clusters) + Git path helpers (only step_*) + step rules (only step_*) + timing constants. It also imports TaskReference from the tracker module: the core depends on a backend type.
attempt_reads
37 importers
Row types + a generic connection base class + as_int/as_text row parsers used by 8 stores. The parsers are a hand-written row mapper, the thing the shelf helper replaces.
operations
25 importers
Result records named after verbs, plus time helpers (used by land and round) and require_database (used by one module).
check_store
20 importers
Its row codecs are imported by hold_store and land_store: one store reaches into another's encoding.
factory_schema
19 importers
The schema + SQL text fragments for every table + current(con), which takes a raw connection.

5. What this says

  • No cycles: the import-linter contracts work. The problem is width, not loops.
  • SQL and sqlite3.Connection cross module edges everywhere: 24 importers, 20 signatures, 12 modules run .execute() outside the store modules.
  • Wiring is repeated because each root and each entry process opens its own store and Git views. One tree needs one builder per process, called once.
  • Stores are reached across clusters (attempt_status, dash_task, hold_facts build or import other clusters' stores): no table has one toucher.
