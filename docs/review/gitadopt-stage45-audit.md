# GITADOPT tl-w7lt.5 — stages 4 and 5

Audit of vendored git_porcelain v0.9.0. `R` = `Repo`, `W` = `Worktree`; `gp.*` = public path-based helpers exported by `git_porcelain`, **not** protocol methods. Signatures below are proposed additions unless identified as existing. Raw `run_git`/`RealRepo.run` can spell commands but do not replace a typed operation or supply its fake contract.

Error mapping: existing `pool_error` maps porcelain write errors to task-loop `SlotGitError` subclasses; `pool_read_error` preserves `MissingRevision`/`NotARepo` and makes unknown observations `GitReadFailure`. Reads must never turn an unknown failure into absence, false, or zero. For proposed outcome operations, `CommandResult(ok: bool, output: str)` preserves complete stripped stdout+stderr and maps directly to `GitOutcome`; git refusal is `ok=False`. Preserve `_try` timeout outcomes (push/LFS: 3600 seconds); invocation `OSError` currently escapes. Successful typed results can map to `GitOutcome(True, "")` only where callers need no success text.

## Stage 4 — REBASE

Sources: `src/taskloop/adapters/git.py`, `git_ops.py`, `git_base.py`; `contracts/ports.py` (`SlotGit`, `Git`); `app/land/{rebase,land_rebase,fixer,salvage,landed,stack,forge}.py`. Porcelain semantics checked in `api.py`, `real_read.py`, `real_write.py`, `history.py`, `real_integrate.py`, `plumbing.py`.

| Task-loop operation / behavior | Existing porcelain replacement | Exact gap, capability wanted, and mapping |
| --- | --- | --- |
| `rebase(d, onto, update_refs=True)`; resume and landing rebases | **Partial:** `W.rebase_onto(base, *, squash_message=None)` | Want `W.rebase_onto(base: str, *, squash_message: str\|None=None, update_refs: bool\|None=None) -> RebaseResult`, where `None` inherits config and `False` overrides it. Current real implementation **always disables** `rebase.updateRefs`; task-loop's default inherits config. Also want `W.rebase(base: str, *, update_refs: bool\|None=None) -> CommandResult` for exact legacy behavior: current porcelain skips execution when `HEAD..base` is empty, rejects dirty/paused state with `ValueError`, and raises for non-conflict failures; old code invokes git and returns every git refusal as `GitOutcome(False, output)`. `UpToDate`/`Rebased` map to success, `Conflict.tail` to failure; other command diagnostics must survive. |
| Resume squash before rebase; restore original HEAD after failed salvage | **Partial:** `W.rebase_onto(base, squash_message=message)`; `W.finish_rebase("abort", restore_to=orig)` | Want `W.rebase_onto(base: str, *, squash_message: str\|None=None, squash_failure: Literal["raise", "continue_unsquashed"]="raise", update_refs: bool\|None=None) -> RebaseResult`. Existing combined operation restores then raises if squash commit fails; `Rebase.squash_wip` restores then **continues unsquashed**. Preserve that policy and report squash failure diagnostics. Abort with `restore_to` otherwise covers the hard reset after a squashed rebase. |
| `rebase_continue(d)` = `-c core.editor=true rebase --continue` after caller stages | **Partial:** `W.finish_rebase("continue")` | Want `W.continue_rebase(*, stage_conflicts: bool=False, check_markers: bool=False, missing_ok: bool=False) -> CommandResult`. Existing finish automatically stages unmerged paths, rejects markers itself, treats no paused rebase as success, and raises for some non-conflict failures. Legacy continuation uses the existing index and git's refusal/output; landing already checks markers and stages via `checkout.stage_all`. |
| `rebase_abort(d)`; best-effort cleanup | **Partial:** `W.finish_rebase("abort")` | Host can discard `Aborted` and suppress command-refusal exceptions to reproduce ignored exit status; do not suppress spawn failures. Want `W.abort_rebase(*, missing_ok: bool=True, restore_to: Sha\|None=None) -> CommandResult` if exact command status is needed: existing finish raises on abort refusal and needs a resolvable HEAD even for a no-op; old adapter ignores git's exit code. |
| `rebasing(d)` reads `rebase-merge` / `rebase-apply` | **NONE** in protocols/public state API | Want `W.rebasing() -> bool`, detecting both backends in the actual worktree git dir. False only for known absence; repository/path/read faults -> `GitReadFailure`. Private `_paused` is not an API; `merge_in_progress` observes `MERGE_HEAD`, not rebase state. |
| `unmerged(d)` for stopped rebase **or merge**, including later independent reads | **Partial:** `gp.unmerged_paths(repo, *, env=None)`; `Conflict.files` | Want `W.unmerged() -> tuple[str, ...]`, preserving NUL-safe path order and validating complete/nonempty records; failures -> `GitReadFailure`. Public helper and private `real_read.unmerged` use unchecked command reads and can return empty on failure; `Conflict.files` is only a prior write result, not a fresh observation. |
| `merge_base(d, a, b)`; empty if either revision missing or no common ancestor | **Partial:** `R.relate(a, b).merge_base` | Want `R.merge_base(a: str, b: str) -> Sha\|None`: `None` only for verified missing revisions or unrelated histories; all other failures -> `GitReadFailure`. `relate` also computes counts and raises on missing inputs; catch typed `MissingRevision` only, with verified absence for git's otherwise-untyped missing-object diagnostic. Map `None` to `""`; never use `tree()` as an absence probe because its resolver suppresses failures. |
| `is_ancestor(d, a, b)`; used for landed detection and push judge | `R.relate(b, a).ahead == 0` | Valid refs, including unrelated histories, are covered; map thrown read errors through `pool_read_error`. Avoid public `gp.is_ancestor(repo, a, b)`: it returns false for every nonzero exit, losing the old predicate's unknown/error distinction. No new capability needed. |
| `cherry(d, upstream, head)` -> ordered `Pick(oid, upstream)` patch-equivalence rows | **Partial:** `R.history([head], not_on=[upstream], patch_equivalent_to=upstream)` | Want `R.cherry(upstream: str, head: str) -> tuple[Pick, ...]` with precisely `git cherry` ordering and commit selection (exclude merge commits), plus +/- patch equivalence. Existing history is newest-first log output, can include merge commits, and labels any row absent from the `+` set equivalent. Its doc also incorrectly constrains `patch_equivalent_to` to a member of `revs`, unlike the real implementation. Refusal -> `pool_error` (old `_must`), never empty success. |
| `count(d, include, exclude)`; ahead/behind checks before resume/land | `R.relate("HEAD", base).ahead / .behind`; general count = `len(R.history(include, not_on=exclude))` | Pairwise and general reachability counts are expressible; preserve old `_must` error mapping via `pool_error`. General history materializes commits but needs no capability addition for correctness. |
| `merged(d, into)`; `merge_ff(d, rev)` | `R.branches()` filtered by `R.relate(tip, into).ahead == 0`; `gp.merge_ff(repo: Path, ref: str) -> None` (`Plumbing`) | Covered by composition/helper; map listing/relation faults with `pool_read_error`, FF refusal with `pool_error`. Public `gp.merge` is unsuitable: it permits a merge commit and disables hooks. |
| `pull_rebase(d, remote, branch)` | `gp.pull_rebase(repo: Path, remote: str, branch: str) -> None` (`Plumbing`) | Covered outside `Repo`/`Worktree`; map `GitError` via `pool_error`. Leaves conflicts paused as before. |
| `merge_tree` / non-mutating merge checks; land-stack rebases | **No such local operation found** in the inspected adapters, Git port, or `app/land` | No current replacement requirement to invent. `Forge.merge` uses `gh pr merge <number> --rebase --match-head-commit <oid>` when configured for rebase; retain forge-side head guarding and PR-state verification. Neither `W.rebase_onto` nor public `gp.merge` substitutes for that remote operation. If a future dry merge check is required: `R.merge_tree(a: str, b: str) -> MergeCheck(tree: TreeId\|None, conflicts: tuple[str, ...], output: str)`, without checkout/index/ref mutation; conflicts are data, missing revisions/infrastructure are read errors. No existing public equivalent. |

## Stage 5 — PUSH / FETCH

Additional sources: `app/land/{outbound,push,cleanup,checkout,stackgate,push_judge}.py`; porcelain `real_refs.py`, `real_config.py`, `lfs.py`, `porcelain.py`. Proposed methods must preserve the adapter's supplied environment and checkout pinning; path-only helpers currently lack the injected `Env` seam.

| Task-loop operation / behavior | Existing porcelain replacement | Exact gap, capability wanted, and mapping |
| --- | --- | --- |
| `push(d, remote, refspec)`; stack pushes immutable `<oid>:refs/heads/<branch>` | **Partial:** `W.push(dst, *, remote="origin", hook_env=None)`; `gp.push(repo, remote=None, refspec=None, *, timeout=120, config=None)` | Public helper already accepts a single explicit refspec and runs hooks; protocol push always pushes current HEAD and prefixes `refs/heads/`. Want `W.push_refspecs(remote: str, refspecs: Sequence[str], *, hook_env: Mapping[str,str]\|None=None, timeout: float\|None=None) -> PushResult` preserving explicit source OIDs and destination namespaces. Map `Pushed` to `None`, failures to `SlotGitError` with push diagnostics. Helper `RemoteError` loses typed lock/ref errors and full combined output; map conservatively, never success. |
| `push_lease(d, remote, refspec)`; accepted-stage `HEAD:refs/heads/task/<bead>` | **NONE** typed lease operation | Want `W.push_lease(remote: str, refspec: str, *, timeout: float=3600) -> CommandResult`, using plain `--force-with-lease` against last fetched tracking refs, normal pre-push hook, and **no** upstream/config changes. Preserve `stale info` diagnostics for cross-machine refusal. Neither protocol push nor a non-forced helper matches; unconditional force is unsafe and semantically different. |
| `delete_remote_at(d, remote, ref, oid)` | **NONE** guarded remote deletion | Want `R.delete_remote_at(remote: str, ref: str, expected: Sha) -> None`, performing `--force-with-lease=<ref>:<oid>` with `:<ref>`. On refusal query advertised ref: authoritative absence succeeds; present ref rethrows original `SlotGitError`; failed verification raises `GitReadFailure`. Public `delete_ref_at` deletes **local** refs only; ordinary push deletion lacks the expected-OID guard. |
| `lfs_push(d, remote, refs: list[str])` before land/WIP pushes | **Partial:** `gp.lfs_push(repo, remote, ref: str, *, timeout=600, config=None)` | Want `W.lfs_push(remote: str, refs: Sequence[str], *, timeout: float=3600) -> CommandResult`: one invocation with all requested refs, no setup/config/hook installation. Existing helper accepts one ref and raises `RemoteError`; looping changes invocation/failure behavior. Keep complete output and timeout -> `GitOutcome(False, "git lfs timed out after 60 min")`; upload failure prevents the ref push. |
| `fetch(d)` = quiet origin fetch with five ref-lock attempts, delays `0.1 * (i+1)` | `R.sync("origin") -> Synced\|Offline` | Existing real implementation already has the same five attempts and delays. Map `Synced` to `None`, **every** `Offline.tail` through host `classify` (including exhausted `RefRace`), and thrown errors through `pool_error`; Offline also represents non-network failures. No retry capability gap. For strict legacy unbounded fetch timing, want `R.fetch(remote: str="origin", *, refspecs: Sequence[str]=(), timeout: float\|None=None) -> None`: sync uses the repository remote timeout rather than the old unbounded invocation. Public `gp.fetch` has no ref-lock retry. |
| `fetch_ref(d, source, ref)` -> `FETCH_HEAD` from repository path/URL | **NONE** scoped fetch | Use proposed `R.fetch(source, refspecs=[ref], ...)`, passing one source ref without inventing a destination/tracking ref; ensure `FETCH_HEAD` is written. Missing remote ref is a failing `SlotGitError`, never absence success. `sync`/public `fetch` accept no refspec. |
| `ls_remote(d, remote, *patterns)`; exact advertised OID, wildcard patterns, authoritative empty response | `gp.ls_remote(repo: Path, remote: str, *patterns: str) -> list[Ref]` (`Plumbing`) | Covered outside `Repo`: map identical `name`/`oid` fields and exceptions through `pool_read_error`. Includes HEAD/peeled tags and git's pattern semantics; empty only after a successful query. No new operation needed. |
| `remote_url(d, remote)`; `MissingRemote` distinct from failed observation | **Partial:** `R.identity().origin_url`; `gp.config_get` | Want `R.remote_url(remote: str) -> str`, matching `git remote get-url` (named remote, URL rewrite rules). Add porcelain `MissingRemote(GitUnavailable)` for exit 2 / exact no-such-remote diagnostic; map to host `MissingRemote`, unknown faults to `GitReadFailure`. Identity only reads origin and suppresses get-url failure into `None`; config lookup neither expands URL rewrites nor preserves missing-remote semantics. |
| Upstream reads and ahead/behind | `R.relate(a,b)` for explicit refs; `gp.upstream(repo)` / `has_upstream(repo)` / `sync_status(repo)` for tracking facts | No dedicated upstream method/call found in task-loop's inspected Git port/adapters/land; configured `base` is explicit. If adopting tracking reads, want `W.upstream() -> str\|None` with absent tracking config/detached HEAD distinguished from unknown faults (`GitReadFailure`). Existing helpers suppress failures; `sync_status` can manufacture zero counts. Use `relate("HEAD", upstream)` for ahead/behind once upstream is known. |
| Landing push via `Sh(pin_head(cfg.land, sha), pin=True)`; pre-push delivery judge | **Partial:** `W.push(..., hook_env=...)`; public explicit-refspec push | Use proposed `push_refspecs` with **captured SHA**, retaining normal hook invocation, repository hooks path, injected environment, full diagnostics, and stop deferral/fence/gate checks in the app. Current protocol rereads HEAD, so a concurrent move can push an unjudged commit. Preserve `Rejected` race retry versus transient/network rest versus hook/other fault; porcelain currently classifies any `!` status as `Rejected`, including hook/remote refusal, so require `PushResult` refinement `RefRejected(tail)` versus `HookRejected(tail)`/`RemoteRejected(tail)` to avoid retrying policy refusal as a moved base. |
| Configured refspec/options forms: `HEAD`, `HEAD:main`, `+HEAD:main`, explicit OID, multiple refs, deletion; custom land command | **Partial:** single-refspec `gp.push`; **NONE** for complete configured command semantics in protocols | Want `W.push_request(remote: str\|None, refspecs: Sequence[str], *, options: Sequence[str]=(), hook_env: Mapping[str,str]\|None=None, timeout: float\|None=None) -> CommandResult`. Preserve force prefix, omitted remote/refspec push defaults, tag/full-ref namespaces, deletion and supplied push options without changing config/upstream. Substitute captured SHA only when the source is exactly HEAD (including `+HEAD`); keep all destinations unchanged. `W.push` accepts only one branch destination. Keep non-git custom commands on `Sh`; no Git API replacement applies. |

Static audit only; no git, bd, tl, uv, just, or test commands run. Only this new file is intentionally created; source files are unchanged.
