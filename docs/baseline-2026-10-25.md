- landed = trace `outcome == landed`. Non-landing = blocked + failed + done (4 `done` runs count as non-landing, as in the study).
- "7 d" window = 2026-10-18 00:00 .. now. Trace data starts 2026-10-18 21:58, so real span is 6.9 d, not 7.84 d; per-day figures below use the calendar span (17.4/day all repos), the span of data gives 19.7/day.

KEY FINDING on provenance: the stage-epic numbers are LIFESIM-ONLY at a snapshot before 10-25 ~10:00. Running `--repo lifesim --now 2026-10-25T10:00` gives exactly: 384 runs, 131 landed, 17,541 slot-min, 134 per landed, 9,773 non-landing (tl-7y6 says 9,774), 59/164 on run 1. So tl-7y6 mixes a lifesim-only denominator with all-repo parked/asks figures. The freeze must name one scope.

## 3. Differences that change a decision

- Mean runs per landed bead is 2.1, not 3.0. 3.0 = all runs / landed beads. Use "retries per landing" 1.1 (2.07 - 1) or all-runs ratio, but name it.
- Run-1 landing is 45% of landed or 36% of touched. 02 and tl-7y6 use different ones; the target in 02 (>= 80%) is stated for the 45% version.
- Asks: withdrawn 45 not 47, answered 39 not 35, open 8 not 11. Percent avoidable is stable (87-88%).
- "9,893 parked slot-min" = 9,912 all-repo = all non-landing time. Real pause time is 1,388 min. Slice-1's "cover 60-70% of 9,893" is a share of non-landing minutes, mostly running time wasted, not idle slots.
- Timeouts: 47-min no-session count is 11 in 48 h (517 session-min), not 5 in 4 days.
- Claude lane median is 44 s, not 21 s.
- The last 48 h are not representative of the week: all Grok/DeepSeek/ZAI traffic, all 47-min no-session timeouts, the 755-min credit pause and 825 of the 2,259 over-budget minutes are there.
